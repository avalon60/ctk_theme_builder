## Persistence and Integration Boundaries

The default writable data root is `~/CTkThemeBuilder`, outside the install
tree. `ctk_tb/paths.py` declares `themes/`, `palettes/`, `state/`, `tmp/`,
`logs/`, `launchers/` and `upgrades/` beneath it. The SQLite file is
`state/ctk_theme_builder.db`; runtime layout and deleted-seed-theme markers
also live under `state/`. The theme-directory preference may override the
default theme location. `ctk_tb/controller/migrate_assets.py` handles legacy
asset migration and also declares current user-data paths.

Theme and palette JSON and SQLite preferences are persisted user contracts.
The package's startup code seeds resources and migrates state; changes need
compatibility checks for existing installations as well as fresh startup.

| Integration | Boundary and evidence |
| --- | --- |
| Desktop display | Tk-capable desktop required for application and widget checks; package metadata supports Linux, Windows and macOS. |
| Update lookup | `ctk_tb/utils/update_check.py` reads PyPI project metadata over the network. |
| Generated launchers/upgrades | `ctk_tb/utils/launcher_generator.py` and `upgrade_script_generator.py` produce user-side launch/update helpers. |
| Legacy bootstrap | `build_app.sh` executes bundled `get-pip.py` and installs requirements. |
| Publication | `utils/publish.sh` uses Twine for PyPI or TestPyPI; creating this context does not authorise uploading. |
| Credential configuration | Twine is the publishing tool; no project-specific secret-store labels confirmed. Do not put credential values in context. |

## Validation and Generated Outputs

Run applicable commands from the repository root. Desktop checks require a
usable Tk session; installed-wheel checks require the documented pyenv Python
version and an available wheel.

| Scope | Recorded validation or command | Evidence |
| --- | --- | --- |
| Package configuration | `poetry check` | Release guide and packaging script. |
| Automated regressions | `poetry run pytest` | pytest configuration selects `tests/`; fixture isolates home state. |
| Wheel and sdist construction | `poetry build` | Poetry backend and release guide. |
| Installed wheel | `./utils/test_wheel_install.sh <python-version> [wheel-path]` | Script creates a scratch virtualenv and installs the selected wheel; follow with imports, entrypoint and resource checks. |
| Release artefacts | `./utils/package.sh -v <release-version>` | Generates distributions, exported requirements, checksums and a release ZIP. |
| Bash changes | `bash -n <changed-script>` | Syntax validation for touched Bash launchers or packaging scripts. |
| GUI changes | Launch the installed application and exercise the affected widgets in applicable light/dark modes | Desktop view and preview implementations; no headless GUI harness confirmed. |

`dist/` and `dist/release/` contain generated packaging outputs. Logs, temporary
files, user state and generated launch/update helpers are runtime artefacts.
Do not infer that creating those outputs authorises staging or publishing them.
See `docs/release-artefact-guide.md` for release-building details and
`docs/installs-upgrades.md` for installation and upgrade guidance.
